# Feature Specification: Надёжный импорт готовых упражнений

**Feature Branch**: `001-reliable-source-ingestion`

**Created**: 2026-08-21

**Status**: Draft

**Input**: Учитель загружает PDF или вставляет текст с готовыми заданиями. Система создаёт
проверяемый черновик урока без потери, переписывания или придумывания упражнений.

## Clarifications

### Session 2026-08-21

- Q: Что должно происходить с публичной ссылкой, если учитель больше не хочет предоставлять доступ к уроку? → A: Ссылка действует бессрочно и не может быть отозвана.
- Q: Какие максимальные размеры одного импорта должны поддерживаться в первой версии? → A: PDF до 20 страниц и 50 МиБ (52 428 800 байт), текст до 500 000 Unicode code points, максимум 500 полей ответа; входные лимиты проверять до создания run, а лимит полей — во время extraction; при превышении просить разделить материал на части и возвращать ошибку.
- Q: Нужно ли объединять части слишком большого материала после их раздельного импорта? → A: Нет. Каждая часть становится самостоятельным импортом и отдельным уроком; объединение частей не входит в первую версию.
- Q: Как обрабатывать одновременное сохранение одного черновика из нескольких вкладок? → A: Использовать оптимистичный контроль версий; устаревшее сохранение отклонять с `409 DRAFT_VERSION_CONFLICT` без перезаписи новых правок.
- Q: Сколько раз автоматически повторять этап импорта при временном сбое? → A: Не повторять автоматически; первый временный сбой останавливает run, после чего учитель может вручную продолжить его с последнего подтверждённого шага.

### Session 2026-08-24

- Q: Что происходит, если durable worker не получил событие или перестал обновлять run до создания draft? → A: Новый run атомарно записывает `accepted` event до dispatch. `accepted` без обновления 30 секунд и `processing` без draft/обновления 3 минуты считаются stale; polling останавливается, учитель видит последнее обновление и может owner-only идемпотентно повторно доставить событие в тот же run. Это отдельный redispatch, не автоматический retry и не `resume` failed run.
- Q: Как локально запускать durable workflow? → A: Корневой `pnpm dev` обязан одновременно запускать Next.js и закреплённый Inngest Dev Server; завершение одного процесса завершает второй с ошибкой.
- Q: Как авторизованный учитель понимает, под каким аккаунтом он работает? → A: На всех teacher-facing страницах верхняя навигация показывает профиль из подтверждённой Supabase-сессии: автоматический аватар, display name/email, ссылки на уроки и создание урока, а также POST sign-out; для анонимного пользователя профиль заменяется входом.
- Q: Как представлять «Complete the sentences with the words in the box», когда один набор слов относится к нескольким пунктам? → A: Набор слов является одним group-level shared resource типа `wordBank`, показывается один раз между инструкцией и первым пунктом, а задания ссылаются на него и не дублируют слова в собственных options.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Точный перенос PDF-теста (Priority: P1)

Учитель загружает страницу теста со сложной вёрсткой и получает черновик, в котором сохранены
названия частей, инструкции, порядок, нумерация, варианты и пропуски всех упражнений.

**Why this priority**: Точный перенос готового теста является главным обещанием продукта и первым
условием доверия учителя.

**Independent Test**: Загрузить `1_page.pdf` и сопоставить каждый элемент черновика с исходной
страницей. Черновик должен содержать пять групп упражнений и 34 оцениваемых пункта без добавлений.

**Acceptance Scenarios**:

1. **Given** PDF с двумя колонками и пятью группами упражнений, **When** учитель запускает импорт,
   **Then** система создаёт пять групп в исходном порядке и учитывает все 34 пункта.
2. **Given** вопрос с тремя вариантами, **When** он попадает в черновик, **Then** формулировка,
   порядок вариантов и ссылка на область исходной страницы сохранены.
3. **Given** задания на порядок слов, глагольные формы, лишнее слово и word bank, **When** импорт
   завершён, **Then** каждый тип представлен как отдельный проверяемый тип взаимодействия.
4. **Given** в PDF отсутствует ключ ответов, **When** черновик создан, **Then** ответы помечены как
   неподтверждённые и урок не публикуется автоматически.
5. **Given** авторизованный учитель выбрал PDF, **When** он отправляет форму импорта, **Then**
   неизменяемый источник сохраняется в пространстве этого учителя, создаётся run и интерфейс
   переходит к отображению прогресса.
6. **Given** один источник и один `idempotencyKey`, **When** одинаковый import request отправлен
   повторно, **Then** система возвращает первоначальный `runId` и не создаёт второй run; повторное
   использование ключа с другим источником возвращает `409`.
7. **Given** run остался `accepted` без запуска worker либо `processing` перестал обновляться до
   создания draft, **When** истекает документированный stale threshold, **Then** UI прекращает
   бесконечный polling, показывает последнее обновление и журнал, а owner-only повторная доставка с
   idempotency key продолжает тот же run без дублирования source, draft или событий доставки.
8. **Given** группа «Complete the sentences with the words in the box» содержит один блок из семи
   слов и семь предложений с пропусками, **When** создаются draft и student lesson, **Then** слова
   сохраняются как один addressable group-level `wordBank`, отображаются один раз над предложениями,
   а каждое `wordBankGap` упражнение ссылается на этот ресурс без копирования банка в свои `options`.

### User Story 2 - Точный перенос вставленного текста (Priority: P1)

Учитель вставляет длинное упражнение с переносами строк, разорванными словами и несколькими
пропусками внутри одного нумерованного пункта. Система сохраняет содержание и создаёт отдельное поле
ответа для каждого глагола в скобках.

**Why this priority**: Вставка текста является самым быстрым и доступным способом создания урока,
но именно здесь переносы и неоднозначная нумерация часто приводят к потере заданий.

**Independent Test**: Импортировать `raw.txt`. Система должна обнаружить 18 нумерованных пунктов и
29 глагольных выражений в скобках, включая два разорванных переносом строки, сохранить их порядок и
4 коротких ответа, отдельно предупредив, что последний пункт
обрывается.

**Acceptance Scenarios**:

1. **Given** текст с разрывами слов и строк, **When** система нормализует его для анализа, **Then**
   исходный текст остаётся неизменным, а нормализованное представление связано с ним ссылками.
2. **Given** один пункт с несколькими глаголами в скобках, **When** создаётся упражнение, **Then** ни
   один пропуск не исчезает и сохраняется порядок всех пропусков.
3. **Given** последний пункт заканчивается незавершённой фразой, **When** импорт завершается,
   **Then** система не дописывает продолжение и создаёт предупреждение для учителя.
4. **Given** авторизованный учитель вставил текст, **When** он отправляет форму импорта, **Then** тот
   же import endpoint принимает текстовый источник, сохраняет оригинал и создаёт отдельный run.

### User Story 3 - Проверка спорных элементов учителем (Priority: P2)

Учитель видит источник и черновик рядом, понимает происхождение каждого элемента и может редактировать
любое поле правильного ответа. Автоматически предложенные ответы остаются `modelInferred` и требуют
явного подтверждения или исправления учителем; только после этого они становятся `teacherSupplied`.

**Why this priority**: Human-in-the-loop позволяет сохранить скорость автоматизации, не выдавая
предположения модели за достоверные данные.

**Independent Test**: Открыть черновик с неподтверждёнными ответами и предупреждением об обрыве,
проверить переход от каждого issue к соответствующему месту источника и подтвердить исправления.

**Acceptance Scenarios**:

1. **Given** элемент черновика, **When** учитель выбирает его, **Then** интерфейс показывает точное
   место в источнике и происхождение всех изменяемых полей.
2. **Given** неподтверждённый правильный ответ, **When** учитель вводит и подтверждает его, **Then**
   ответ получает происхождение «teacher supplied» и фиксируется в журнале решений.
3. **Given** неразрешённая ошибка полноты, **When** учитель пытается опубликовать урок, **Then**
   публикация блокируется и показывается конкретная причина.
4. **Given** один черновик открыт в двух вкладках с одинаковой исходной версией, **When** первая
   вкладка успешно сохраняет изменения, а затем вторая пытается сохранить устаревшую версию,
   **Then** второе сохранение получает `409 DRAFT_VERSION_CONFLICT`, не изменяет черновик и предлагает
   обновить данные перед повторным внесением правок.
5. **Given** модель предложила значение для неразрешённого answer field, **When** учитель открывает
   review, **Then** поле остаётся редактируемым, помечено как `modelInferred` и не считается
   подтверждённым до отдельного действия учителя.
6. **Given** учитель подтверждает предложенное значение без изменений либо исправляет его, **When**
   review сохраняется, **Then** ответ получает provenance `teacherSupplied`, а append-only
   ReviewDecision фиксирует исходное предложение, итоговое значение и действие учителя.
7. **Given** draft уже появился, **When** review UI получил его в очередном status response, **Then**
   UI прекращает polling и не создаёт последующих status-запросов до явного действия учителя.

### User Story 4 - Проверяемая публикация версии (Priority: P3)

После устранения обязательных предупреждений учитель публикует неизменяемую версию урока и может
позднее создать новую версию, не теряя предыдущую.

**Why this priority**: Версионирование необходимо для безопасного редактирования, но становится
полезным только после надёжного импорта и review.

**Independent Test**: Опубликовать проверенный черновик, изменить один вопрос и убедиться, что
создана новая версия с видимым diff, а старая версия остаётся доступной.

**Acceptance Scenarios**:

1. **Given** черновик без блокирующих ошибок, **When** учитель публикует его, **Then** создаётся
   неизменяемая версия с отчётом валидации.
2. **Given** опубликованный урок, **When** учитель начинает редактирование, **Then** создаётся новый
   черновик, а опубликованная версия не изменяется.
3. **Given** опубликованный урок и его публичный ID, **When** ученик без авторизации открывает ссылку,
   **Then** он получает последнюю опубликованную student-safe версию; после публикации новой версии
   та же ссылка показывает её, неизвестный или неопубликованный ID возвращает тот же `404`, а
   публичного списка уроков нет.
4. **Given** урок был опубликован хотя бы один раз, **When** учитель позднее редактирует урок или
   прекращает использовать его, **Then** исходный публичный ID продолжает бессрочно открывать
   последнюю опубликованную student-safe версию и не может быть отозван, отключён или заменён.
5. **Given** урок ещё не публиковался, **When** учитель начинает первую публикацию, **Then** интерфейс
   явно предупреждает о бессрочной публичной доступности и отсутствии revoke, disable и rotate,
   а публикация выполняется только после отдельного явного подтверждения учителя.
6. **Given** любой publish-readiness invariant не выполнен, **When** workflow сохраняет или
   пересчитывает черновик, **Then** run остаётся `awaiting_review`, а `ready_to_publish` выставляется
   только при пустом canonical `reasons`; попытка публикации возвращает и показывает тот же список
   конкретных причин.

### Edge Cases

- PDF является сканом без текстового слоя: первая версия создаёт блокирующий `OCR_REQUIRED`, не
  публикует пустой урок и предлагает учителю загрузить текстовый PDF или вставить текст. Участки с
  низкой уверенностью создают адресуемые review issues.
- В документе одновременно присутствуют объяснения, примеры, упражнения и ключ ответов.
- Нумерация упражнений начинается заново внутри новой секции.
- Один оцениваемый пункт содержит несколько независимых пропусков.
- Ответы приведены на другой странице или используют отличающуюся нумерацию.
- Вариант ответа или предложение переносится между колонками или страницами.
- Материал заканчивается посередине инструкции, предложения или упражнения.
- Текст документа пытается дать системе инструкции, не относящиеся к учебному содержанию.
- Повторная отправка одного запроса или восстановление после сбоя не создаёт дубликаты.
- Временный сбой модели, сети или внешнего сервиса: run сразу переходит в состояние восстанавливаемой
  ошибки без автоматического повтора; интерфейс предлагает учителю вручную продолжить обработку.
- Формат не поддерживается или исходный файл повреждён.
- PDF превышает 20 страниц или 50 МиБ (52 428 800 байт) либо вставленный текст превышает 500 000
  Unicode code points до нормализации: система
  отклоняет источник до persistence и не создаёт source, run или draft; ответ содержит
  `SOURCE_TOO_LARGE` и предлагает разделить материал на несколько самостоятельных уроков.
- Во время extraction обнаружено более 500 полей ответа: существующий run завершается терминальной
  ошибкой `SOURCE_TOO_LARGE`, draft не создаётся, а интерфейс предлагает разделить исходный материал
  на несколько самостоятельных уроков.
- Пользователь импортирует несколько частей одного большого материала: каждая часть создаёт отдельный
  run, отдельный черновик и при публикации отдельный урок; система не объединяет части автоматически.
- Durable event принят API, но worker не начал run, либо `processing` run перестал обновляться до
  создания draft: UI отличает stale delivery от активной работы, прекращает polling и предлагает
  безопасный owner-only redispatch того же run.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST принимать PDF и вставленный текст как независимые виды источников.
- **FR-002**: Система MUST сохранять неизменяемый оригинал и отделять его от всех производных
  представлений.
- **FR-003**: Система MUST представлять страницы, блоки, порядок чтения, таблицы и области источника
  так, чтобы производные элементы могли ссылаться на точное место происхождения.
- **FR-004**: Система MUST классифицировать отдельные секции материала, а не требовать единого режима
  для всего документа.
- **FR-005**: Система MUST обнаруживать инструкции, группы упражнений, оцениваемые пункты, варианты,
  пропуски, word bank и возможные ключи ответов.
- **FR-006**: Каждый перенесённый элемент MUST иметь стабильный идентификатор и как минимум одну
  ссылку на источник.
- **FR-007**: Система MUST сохранять исходный порядок, вложенность и нумерацию упражнений.
- **FR-008**: Система MUST отдельно учитывать группу упражнений, нумерованный пункт и поле ответа.
- **FR-009**: Система MUST формировать отчёт покрытия, объясняющий судьбу каждого обнаруженного
  кандидата.
- **FR-010**: Система MUST блокировать автоматическую публикацию при пропущенном кандидате,
  неподтверждённом изменении источника или необъяснимом добавленном упражнении.
- **FR-011**: Система MUST поддерживать на первом этапе single choice, word order, bracket gap,
  odd-one-out и word-bank gap.
- **FR-012**: Система MUST сохранять происхождение ответа: source key, teacher supplied,
  deterministic rule или model inferred.
- **FR-013**: Если достоверный ключ отсутствует, система MUST оставлять ответ неподтверждённым, а не
  представлять предположение как факт.
- **FR-014**: Учитель MUST видеть источник, черновик, предупреждения и происхождение данных в одном
  review-процессе.
- **FR-015**: Учитель MUST иметь возможность подтвердить, исправить или исключить спорный элемент с
  сохранением причины и истории решения.
- **FR-016**: Опубликованный урок MUST быть неизменяемым; последующие правки MUST создавать новую
  версию.
- **FR-017**: Повторное выполнение одного шага MUST давать эквивалентный результат и не создавать
  дублирующие опубликованные сущности.
- **FR-018**: Система MUST сохранять отчёт выполнения, включающий версии преобразований, результаты
  проверок, предупреждения и пользовательские решения.
- **FR-019**: Содержимое источника MUST рассматриваться как недоверенные данные и не может изменять
  правила обработки или запрашивать действия вне импорта.
- **FR-020**: Система MUST выдавать понятный статус для завершённого импорта, ожидания проверки,
  блокировки, восстанавливаемой ошибки и окончательного сбоя. API MUST представлять оба вида сбоя
  статусом `failed` и машинно различать их через `failure.kind`: `retriable` разрешает ручное
  продолжение, `terminal` запрещает его; статус `retrying` и время следующей автоматической попытки
  MUST NOT использоваться.
- **FR-021**: Только авторизованный владелец MUST иметь доступ к исходнику, run, draft, issues,
  решениям и версиям урока; API и файловое хранилище MUST независимо проверять ownership.
- **FR-022**: Система MUST сохранять оригинальный источник и производные артефакты бессрочно в рамках
  жизненного цикла продукта, чтобы опубликованные версии оставались проверяемыми; пользовательское
  удаление источников, автоматический purge и очистка заброшенных imports не входят в эту feature;
  database relations MUST запрещать каскадное удаление источника, а source persistence API MUST не
  предоставлять delete operation.
- **FR-023**: Ученический интерфейс MUST получать отдельный student-safe контракт без правильных
  ответов, accepted values, answer provenance и внутренних validation details; опубликованный урок
  MUST быть доступен без авторизации только по криптографически непредсказуемому стабильному
  публичному ID, который разрешается в последнюю опубликованную версию урока. После первой
  публикации публичный ID MUST действовать бессрочно и MUST NOT поддерживать отзыв, временное
  отключение или ротацию. До первой публикации интерфейс MUST показать отдельное предупреждение об
  этой необратимости и получить явное подтверждение учителя.
- **FR-024**: Каждый вариант ответа MUST быть отдельной сущностью со стабильным ID и иметь хотя бы
  одну ссылку на источник либо ссылку на документированное решение учителя.
- **FR-025**: Система MUST предоставлять единую точку старта импорта для PDF и текста, которая
  валидирует источник, требует `idempotencyKey`, сохраняет его вместе с fingerprint запроса, создаёт
  run ровно один раз и запускает durable workflow. Повтор того же ключа и fingerprint MUST возвращать
  исходный `runId`; тот же ключ с другим fingerprint MUST возвращать `409`.
- **FR-026**: Один import MUST принимать PDF не более 20 страниц и 50 МиБ (52 428 800 байт) либо
  вставленный текст не более 500 000 Unicode code points, подсчитанных в исходном тексте до
  нормализации; результат MUST содержать не более 500 полей ответа. Страницы, байты и
  символы MUST проверяться до persistence: превышение MUST вернуть `413` с кодом
  `SOURCE_TOO_LARGE`, типом лимита, лимитом и фактическим значением без создания source, run или
  draft. Лимит полей MUST проверяться во время extraction: превышение MUST завершить уже созданный
  run терминальной ошибкой `SOURCE_TOO_LARGE` без создания draft. В обоих случаях интерфейс MUST
  предложить разделить материал на части и пояснить, что каждая часть станет отдельным уроком.
- **FR-027**: Каждая часть разделённого пользователем материала MUST обрабатываться как независимый
  import с собственными source, run, draft и опубликованным уроком. Система MUST NOT автоматически
  или вручную объединять несколько импортов в один урок в рамках этой feature.
- **FR-028**: Каждая изменяющая черновик операция MUST передавать ожидаемую версию черновика и
  атомарно увеличивать её при успешном сохранении. При несовпадении ожидаемой и актуальной версии API
  MUST вернуть `409 DRAFT_VERSION_CONFLICT`, не применять ни одну часть изменения и предоставить
  клиенту возможность загрузить актуальное состояние; автоматическое слияние не выполняется.
- **FR-029**: Workflow MUST NOT автоматически повторять этап после временного сбоя модели, сети или
  внешнего сервиса. Первый такой сбой MUST остановить run как восстанавливаемую ошибку и предложить
  учителю ручное продолжение с последнего успешно сохранённого checkpoint; ручное продолжение MUST
  быть доступно только владельцу, требовать idempotency key, быть идемпотентным и не дублировать уже
  созданные артефакты. Terminal failure MUST NOT поддерживать продолжение.
- **FR-030**: Модель MAY предлагать ответы только для существующих неразрешённых answer field через
  один bounded-вызов с versioned prompt, typed output и evidence из соответствующих SourceRef.
  Предложение MUST сохраняться только как `modelInferred`; каждое поле MUST оставаться редактируемым,
  требовать отдельного confirm/edit и после сохранения MUST становиться `teacherSupplied` с
  append-only ReviewDecision. Модель MUST NOT создавать, удалять или перестраивать упражнения.
- **FR-031**: Review UI MUST прекратить polling сразу после получения draft. Сбой bounded model step
  MUST следовать lifecycle из FR-029, сохранять checkpoint и не запускать автоматический retry.
- **FR-032**: Все переходы в `ready_to_publish` и сам publish endpoint MUST использовать один
  canonical publish-readiness validator: отсутствие открытых blocking issues и unsupported
  additions, только verified non-empty answers и валидная repository-backed SourceRef lineage. При
  невыполнении хотя бы одного invariant run MUST оставаться `awaiting_review`; API MUST вернуть
  structured `PUBLISH_BLOCKED.reasons`, а publish UI MUST показать каждую причину пользователю.
- **FR-033**: Создание нового run MUST атомарно сохранять ordered `accepted` event до внешнего event
  dispatch. Status API MUST возвращать `updatedAt` и structured recovery state для `accepted` без
  обновления не менее 30 секунд и `processing` без draft/обновления не менее 3 минут. Review UI MUST
  остановить polling при таком recovery state, показать последнее обновление и ordered event log.
- **FR-034**: Владелец MUST иметь отдельную idempotent redispatch operation для stale `accepted` или
  `processing` run без draft. Atomic claim MUST запрещать конкурентную повторную доставку, другой run
  с тем же ключом, non-stale run и run с draft. Redispatch MUST продолжать тот же run и MUST NOT
  считаться automatic retry либо заменять manual resume из FR-029. Локальный `pnpm dev` MUST запускать
  Next.js и version-pinned Inngest Dev Server как единый lifecycle.
- **FR-035**: После успешной авторизации каждая teacher-facing страница MUST показывать в верхней
  навигации профиль текущего пользователя, полученный только из серверно проверенной Supabase session.
  Профиль MUST содержать автоматически созданный аватар с инициалами, display name с безопасным
  fallback на email, сам email в раскрытом dropdown, переходы к урокам и новому импорту и POST sign-out.
  Главная страница MUST заменять CTA входа этим профилем при активной сессии; student page MUST
  оставаться доступной без авторизации и не зависеть от teacher profile.
- **FR-036**: Общий материал, относящийся к нескольким упражнениям группы, MUST храниться как
  addressable `sharedResource`, а не дублироваться в каждом упражнении. Для `kind = wordBank` ресурс
  MUST содержать стабильный ID, ordinal, отдельные provenance-bearing entries и `usagePolicy` со
  значением `useOnce`, `reusable` или `unspecified`; extractor MUST NOT выводить политику, которой нет
  в источнике. Каждое `wordBankGap` MUST ссылаться на group-level word bank через `sharedResourceId`,
  иметь пустой локальный `options` и сохранять собственные prompt, answer fields и provenance. Review
  и student UI MUST показывать банк один раз после инструкции группы и до первого использующего его
  упражнения. Student-safe projection MUST включать display entries и usage policy, но MUST NOT
  включать accepted answers или answer provenance.

### Key Entities

- **Source Document**: Неизменяемый загруженный файл или текст с владельцем и контрольной суммой.
- **Source Block**: Адресуемый фрагмент источника с порядком чтения и координатами происхождения.
- **Exercise Candidate**: Потенциальная инструкция, группа, пункт, вариант, пропуск или ключ до
  окончательного включения в урок.
- **Exercise Draft**: Структурированное упражнение, связанное с кандидатами и доступное для review.
- **Shared Exercise Resource**: Общий для нескольких упражнений материал группы. Первая версия
  поддерживает `wordBank`; каждое слово остаётся отдельной адресуемой entry с provenance, а упражнения
  хранят только ссылку на ресурс.
- **Answer Record**: Ожидаемый ответ, допустимые варианты, происхождение и статус проверки.
- **Validation Issue**: Машиночитаемое отклонение с уровнем важности, доказательствами и статусом.
- **Coverage Report**: Сопоставление всех кандидатов источника с упражнениями, issues или решениями.
- **Review Decision**: Неизменяемая запись подтверждения, исправления или исключения учителем.
- **Lesson Version**: Неизменяемый опубликованный набор упражнений и отчёт его проверки.
- **Public Lesson ID**: Независимый от внутреннего ID URL-safe capability token с энтропией не менее
  128 бит, создаваемый при первой публикации и используемый анонимным ученическим интерфейсом.
- **Generation Manifest**: Метаданные конкретного выполнения, позволяющие воспроизвести и сравнить
  результат.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Для `1_page.pdf` система сохраняет все 5 групп и все 34 оцениваемых пункта; число
  неподтверждённых добавлений равно нулю.
- **SC-002**: Для `raw.txt` система учитывает все 18 нумерованных пунктов, все 29 выражений в скобках
  и 4 коротких ответа, не дописывает оборванный пункт и создаёт предупреждение об обрыве.
- **SC-003**: Каждый опубликованный вопрос, вариант и поле ответа имеет ссылку на исходный фрагмент
  либо документированное решение учителя о создании нового элемента.
- **SC-004**: Ни один урок с блокирующей ошибкой полноты или неподтверждённым правильным ответом не
  публикуется автоматически.
- **SC-005**: После прерывания на любом шаге повторный запуск продолжает работу без дублирования уже
  подтверждённых результатов в 100% сценариев восстановления набора тестов.
- **SC-006**: Учитель может перейти от validation issue к соответствующему месту источника не более
  чем за два пользовательских действия.
- **SC-007**: Изменение опубликованного урока всегда создаёт отдельную версию, а предыдущая версия
  остаётся доступной в 100% сценариев версионирования.
- **SC-008**: На контрольном наборе готовых упражнений доля придуманных системой оцениваемых пунктов
  равна нулю.
- **SC-009**: Все cross-tenant запросы к API, database и source storage отклоняются в 100% security
  test cases.
- **SC-010**: Каждый опубликованный урок получает URL-safe публичный ID с энтропией не менее 128 бит;
  ученик открывает урок без авторизации, после публикации v2 тот же ID возвращает v2, а неизвестный
  или неопубликованный ID всегда получает `404`; в 100% lifecycle test cases ID опубликованного урока
  остаётся неизменным и доступным бессрочно, а teacher API и UI не содержат revoke, disable или
  rotate операции; первая публикация невозможна без явного подтверждения предупреждения.
- **SC-011**: Student-safe API и rendered page не содержат правильных ответов, accepted values или
  answer provenance в 100% contract и browser test cases.
- **SC-012**: Валидный PDF или текст принимается и получает `runId` не более чем за 2 секунды в p95
  контрольного окружения без ожидания завершения обработки.
- **SC-013**: В 100% boundary tests значения ровно на каждом лимите принимаются; PDF или текст выше
  входного лимита не создаёт source, run или draft и получает `413 SOURCE_TOO_LARGE`, а превышение
  500 полей завершает созданный run терминальной `SOURCE_TOO_LARGE` без draft. Каждый ответ содержит
  инструкцию разделить материал на самостоятельные уроки.
- **SC-014**: В 100% concurrency test cases устаревшее сохранение получает
  `409 DRAFT_VERSION_CONFLICT` и не изменяет ни одного поля актуального черновика.
- **SC-015**: В 100% failure-injection test cases временный сбой не вызывает автоматический повтор,
  а одно ручное продолжение возобновляет тот же run с последнего checkpoint без дублирования ранее
  сохранённых артефактов.
- **SC-016**: В 100% publish-readiness regression cases статус `ready_to_publish` эквивалентен
  пустому списку canonical block reasons; каждый `409 PUBLISH_BLOCKED` отображает все полученные
  `reasons` без замены общим сообщением.
- **SC-017**: Для version-pinned модели и prompt на `1_page.pdf` bounded answer-suggestion evaluation
  MUST вернуть ровно все 34 известных answerFieldId, не вернуть неизвестных ID и не изменить ни
  одного упражнения; после документированной trim/case/whitespace/punctuation normalization не менее
  90% полей MUST совпасть хотя бы с одним teacher-verified golden answer. Любая смена model, prompt,
  input/output schema или normalization policy MUST создать сравнимый baseline report и пройти этот
  gate до изменения production baseline.
- **SC-018**: В 100% stale-dispatch tests новый run имеет `accepted` event до dispatch; до threshold
  recovery отсутствует, после threshold polling прекращается и owner-only idempotent redispatch
  создаёт не более одного claim/event для одного ключа, не создавая новый run или draft.
- **SC-019**: В 100% navigation contract tests активная teacher session заменяет вход на профиль;
  dropdown показывает сгенерированный avatar, имя/email, ссылки на уроки и импорт и выполняет выход
  только POST-запросом, а отсутствие session не раскрывает данные предыдущего пользователя.
- **SC-020**: Для группы 5 в `1_page.pdf` draft, published и student-safe contracts содержат ровно
  один `wordBank` из 7 addressable entries и 7 ссылающихся `wordBankGap` items; банк отображается
  ровно один раз над пунктами, локальный `options` каждого пункта пуст, а правильные ответы не
  попадают в student payload.

## Assumptions

- Первые regression fixtures предназначены для обучения английскому языку, но сущности ядра не
  ограничиваются одним языком или дисциплиной.
- Если пользователь разделяет слишком большой материал, он принимает, что части станут отдельными
  уроками; сохранение сквозной нумерации и связей между такими уроками не гарантируется.
- В первой feature не требуется генерировать новые упражнения из свободного учебного материала.
- Если источник не содержит ключей, нормальным результатом является черновик, ожидающий проверки.
- Учитель имеет законное право загружать и использовать предоставленные материалы.
- Оригинальный PDF сохраняется для проверки происхождения; визуальная вёрстка не обязана
  воспроизводиться пиксель-в-пиксель в интерфейсе ученика.
- Урок для ученика появляется только после явной публикации проверенной версии.
- Авторизация первой версии использует сессию учителя; анонимное создание и редактирование уроков не
  поддерживается.
- Ученик не обязан авторизовываться: публичный ID урока является capability link, не индексируется и
  не должен быть последовательным, коротким либо выводимым из внутреннего ID.
- Публикация публичной ссылки необратима: feature не предоставляет unpublish, revoke, disable или
  rotate операции для публичного ID, поэтому учитель должен видеть это предупреждение до публикации.
- Политика хранения из FR-022 является исходным продуктовым решением; удаление аккаунта и выполнение
  обязательных юридических запросов на удаление данных требуют отдельной feature и migration plan.

## Out of Scope

- Генерация новых упражнений из статьи, лекции или свободного конспекта.
- Автономное определение правильных ответов без review и доказательств.
- Полноценный редактор учебного курса из нескольких уроков.
- Объединение нескольких импортов или частей исходного материала в один урок.
- Telegram-уведомления и аналитика результатов учеников.
- Пользовательское удаление источников, автоматическая очистка и purge workflow.
- Предметные правила математики, истории и других дисциплин кроме базовой расширяемости схем.
